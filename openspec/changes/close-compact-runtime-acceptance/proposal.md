## Why

The current SkillGuard `0.7.7` source has the compact runtime shape, but the closeout audit found that its self-check entry still accepts file-presence checks, the real consumer projection cannot import its declared minimal closure in an isolated environment, and shared evidence directories can misreport execution counts under concurrency. A single current acceptance change is required to close these gaps without restoring the retired platform, compatibility readers, migration paths, or fallback routes.

## What Changes

- Establish one frozen C00 starting identity and one ordered C01-C03/C08-C12 acceptance path for evidence denominators, consumer closure, self-audit, protection migration, test collection, measurement, and delivery evidence.
- Rebuild the accepted contract from the complete current declared-check inventory and count executions at the actual process-start boundary, preserving `NOT_RUN`, failure, cancellation, attach, timeout, persistence, and cleanup states.
- Make the compact consumer projection importable and runnable in a clean isolated interpreter with only its explicit closure; keep author-only modules, FlowGuard, old `run_store`, and root-search fallback out of the consumer.
- Replace the three self-check file-presence checks with the real admission, execution, and release self-runner, using exact collected test identities and the full current protection denominator, including the newly mapped cases.
- Finish the retained test/protection migration and collection accounting, add the required cross-Guard independence and measurement fixture journeys, and keep final full pytest/installation/package/release claims separate.
- Freeze source, test, contract, toolchain, environment, owner-plan, native/self evidence, and measurement identities before any package or future patch release.

## Capabilities

### New Capabilities

- `compact-runtime-acceptance`: Cross-cutting acceptance contract for C00-C13, covering exact SkillGuard evidence identity, compact consumer independence, real self-audit, protection ownership, test collection, measurements, and delivery freeze.

### Modified Capabilities

No historical capability is replaced by this change. The new acceptance capability consumes the existing `native-depth-evidence-identity`, `universal-execution-depth`, and `skillguard-author-entry-loading` contracts; any remaining closeout requirement is expressed in the new capability so historical OpenSpec changes remain immutable.

## Impact

The implementation scope is limited to the SkillGuard compact state, execution records, checker engine, contract compiler/schema, runtime fingerprint, installation and target-installation transaction, consumer distribution/entrypoint, self-runner, retained tests/protection maps, CI owner configuration, and delivery evidence. It does not alter the historical OpenSpec changes, the already published `v0.7.7` tag/release, the user's installed skill, or GitHub publication. FlowGuard integration is an external acceptance dependency and is coordinated by the same-named change in the FlowGuard repository.



## 2026-09-22 audit delta

The earlier checked receipts describe the historical v0.7.8 state and are not current proof for the next patch.
