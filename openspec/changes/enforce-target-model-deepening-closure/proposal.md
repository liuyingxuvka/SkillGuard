## Why

SkillGuard already requires target-owned depth profiles, exact check inventories, current receipts, and clean consumer projections. It does not need to decide domain depth, but its maintained target contracts must explicitly include the target's iterative model-deepening closure check so a one-shot or prose-only result cannot graduate.

## What Changes

- Add target-owned model-deepening closure obligations to the affected maintained contracts and check manifests.
- Add known-bad fixtures proving that self-reported understanding, open addressable gaps, stale receipts, and no-progress iterations block graduation.
- Keep SkillGuard domain-neutral and consume target-native receipts opaquely.
- Refresh local source/compiled contract/projection parity and author-side documentation.

## Capabilities

### New Capabilities
- None. This extends the existing universal execution-depth supervision.

### Modified Capabilities
- `universal-execution-depth`: require declared target-native iterative closure checks.

## Impact

- SkillGuard contract-source inputs, depth profiles, fixtures, tests, references, and local consumer staging.
- No domain evaluator, understanding-level schema, cross-unit receipt reuse, or consumer SkillGuard dependency.
