# Validated Template Pack Supervision

Load this reference only when the selected maintained target explicitly declares a current validated-template-pack route. The target owns domain applicability, candidates, builders, validators, semantics, and harvest decisions. SkillGuard supervises identities and evidence; the global router never selects a domain template.

## Selection

1. Ask the selected target skill for its current native route receipt before consulting the target catalog.
2. Freeze the exact target, native owner/route, catalog revision/fingerprint, candidate manifests, task facts, parameters, and target-authored applicability plus forbidden-condition evidence.
3. Reconcile the full candidate inventory:
   - zero eligible domain candidates may use only an explicitly declared eligible validated base; otherwise `no_match` blocks;
   - one eligible candidate selects exactly that candidate;
   - many candidates compose only when dependencies, pairwise compatibility, declared order, dominance rules, and single leaf-field ownership are complete; otherwise ambiguity blocks.
4. Materialize a read-only preview. Preserve every selected/rejected candidate and its reason. Keyword scoring, guessed family semantics, last-writer-wins, hidden candidates, stale identities, or fallback are forbidden.

The selection receipt is planning evidence only; it proves neither instantiation nor domain closure.

## Instance

Bind the instance to one current selection receipt, exact parameters, target builder identity, declared field owners, and complete selected manifests. Generated artifact inventory must equal the selected manifests, and every output must be scanned for unresolved placeholders.

Consume every target-declared native validator receipt. Failed, skipped, stale, blocked, not-run, wrong-subject, or foreign-owner validation keeps the instance blocked. Keep the instance fingerprint distinct from source, contract, installed projection, package/runtime, Git, tag, and release identities.

A template supplies structure only. It cannot supply task purpose, protected failures, applicability, semantic PASS, prediction license, empirical truth, installation, or release.

## Installation

Stage only the compiler-owned clean consumer projection and verify exact content before activation. Activate transactionally; run installed currentness separately from native validation. If a required post-activation currentness check fails, restore the previous active projection and preserve recovery evidence.

Refresh the private global router only when the target route projection changes. Never export SkillGuard contracts, receipts, router/Portfolio state, author paths, or `.skillguard` into the consumer.

## Prompt projection

For an applicable target, generation places this complete target-owned guidance in `references/validated-template-pack.md` and places only a short conditional trigger and relative pointer in the target `SKILL.md`. The reference and pointer are part of the target's clean installation identity. A target without validated-template support receives neither.

## Harvest and claim boundary

After a new or materially deepened reusable model, require the target's harvest disposition. Selection, instance, validator, installation, and harvest states remain separate.

SkillGuard can prove that the target's exact template lifecycle was selected, built, checked, projected, and installed under current identities. It does not decide the target's domain template, reinterpret native results, prove factual truth, or prove Git/tag/GitHub Release unless those authorities are checked separately.
