# SkillGuard current design

SkillGuard is an author-side supervisor for explicitly registered skill
maintenance units. It verifies exact contract, check, owner, evidence, clean
consumer projection, installation, and release identities while leaving the
target skill responsible for domain behavior and native checks. Ordinary
consumer installations must remain independent of SkillGuard author state.

The declared-check-supervision model owns the contract that every declared
semantic check has one exact owner, one subject, one unit, and one terminal
evidence projection; missing, foreign, duplicate, or stale evidence must block.

The reverse surface-closure model owns the opposite denominator as well. It
discovers the target's real commands, entry scripts, exports, routes, action
surfaces, artifacts, and failure/recovery boundaries, then requires each
discovered row to have a typed disposition and an explicit current intent,
contract path, native check, owner, and receipt. A declaration-only green result
does not prove that an undiscovered or undeclared surface is safe. An unknown
row remains blocked; it is never silently classified as internal or
not-applicable.

At the current direct-rewrite checkpoint, the source observer finds 1,848
observations across 166 production files for the SkillGuard target. They form
1,398 review groups (1,336 independently addressable surfaces and 512 grouped
implementation facets). A row is an observed public surface or derived facet;
it is not a source-code line. The source span is only an audit anchor. The
author inventory has been rebuilt against the current source fingerprint and
the self-check/depth structural gates pass; execution, installation, consumer,
and release claims remain separate gates and are not implied by this result.

Current authority is direct replacement only. A stale or identity-mismatched
contract, model, manifest, receipt, or installation projection is rejected as
non-current. The maintainer may use the old material as provenance while
manually rewriting the current artifact to the latest schema and re-running its
checks, but SkillGuard has no compatibility reader, automatic migration,
fallback success path, alias, or parallel authority.

The development-process-flow model owns the lifecycle ordering from frozen
source and impact planning through focused validation, one final full owner,
consumer projection, installation currentness, and bounded release claims.

The validation-composition model owns the TestMesh denominator, dependency and
component closure, exact receipt reuse rules, timeout cleanup, and aggregation
boundaries; a plan or report cannot substitute for an executed owner receipt.
